Send an event once. Every endpoint gets it.

A self-hostable webhook delivery service in Go and Postgres. It fans each event out, signs it, retries for about 23 hours and records every attempt.

How it works

One Go binary, one Postgres database

No Kafka, Redis or Kubernetes. The API and the dispatchers share nothing but Postgres, so you can run as many of each as you need.

See the full architecture diagram

The interactive version links every box to its source code.

Failure handling

Delivered at least once, even through crashes

Every request carries a stable webhook-id, so a receiver can safely drop a repeat.

Circuit breaker
10 straight failures pause an endpoint. A probe reopens it.
Retry-After
Honoured on 429 and 503, up to 24 hours.
Auto-disable
After 5 days of failure, with an endpoint.disabled event.
Pause
A paused endpoint keeps queueing and catches up on resume.
Replay
Resend any delivery with the same webhook-id.

Fairness

One slow customer can't stall everyone else

Each endpoint gets at most 4 sends at once. Switch the cap off to see the outage it prevents.

The queue is a table

The delivery row is the queue item. No outbox, no broker.

Limits without Redis

Caps and GCRA rate limits live in the endpoint row, shared by every replica.

The lease is a fencing token

A dispatcher frozen past its lease cannot overwrite a newer result.

Safe in both directions

Standard Webhooks signatures for receivers, and an SSRF guard that refuses private addresses.

Idempotent sends

A repeated Idempotency-Key returns the original. Reusing it with a different body gets a 422.

Bounded storage

Attempts are partitioned by day, and finished messages are deleted after 30 days.

Quickstart

A verified delivery in under a minute

Needs Docker. Starts the stack, sends one event and waits for it to arrive.

sh
git clone https://github.com/rishirajpal01/webhook-delivery-platform
cd webhook-delivery-platform
docker compose up --build -d --wait
ctl() { docker compose exec -T webhookd webhookctl "$@"; }

# An app, and an endpoint pointing at the mock receiver
APP=$(ctl -o '{{.id}}' apps create demo)
ctl endpoints create "$APP" http://mockreceiver:9000/hooks -events order.paid \
  -secret whsec_ZGVtby1zZWNyZXQtZm9yLWxvY2FsLWRldi1vbmx5ISE=

# Send an event and wait until it is delivered
MSG=$(ctl -o '{{.id}}' send "$APP" order.paid '{"order_id":"981","amount":4999}')
ctl deliveries "$APP" "$MSG" -wait 5m

For developers

The spec is the source of truth

  • OpenAPI 3.1 with contract tests against the server and SDK.
  • Go SDK with VerifyRequest for receivers.
  • webhookctl CLI and Prometheus metrics.
  • Configurable: retries, circuit breaker, lease and connection pool are environment settings.
